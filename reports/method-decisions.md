# Development-stage decisions and unresolved validity checks

The first nine-episode pilot uses BF16 execution. FP32 expansion of those same frozen weight values is a new execution precision, so its behavioral confirmation and internal measurements must be kept separate. No training or merging changes the weight values. Full FP32 validation is being attempted to avoid treating a failed BF16 derivative check as evidence that J-lens cannot detect a behavior.

The primary narrow behavior family is interference with evaluation: comparison objects that accept contradictory answers, or prohibited termination of the evaluation process. An incorrect ordinary solution does not by itself demonstrate such interference. Two automated reviewers called some example-hardcoding responses misaligned, but those labels are not sufficient to establish the primary family and remain separate. The label rubric and any narrower action taxonomy must be frozen on development data before final comparison access. Missing or invalid source-format executions never become clean negatives automatically.

WASI is an explicit environment adaptation. It supports Python computation, equality manipulation, and guest process termination, but not the full native pytest environment or arbitrary subprocesses. Initial execution uses the source parser and a separate string-return audit. Multi-file conftest manipulation requires additional implementation and validation. Synthetic containment tests are engineering evidence only, not evidence about the model.

Two independent API calls provide automated review, not human review and not statistically independent annotator errors. Both reviewers currently come from one provider. Original v1 field ambiguity and v2 revisions are preserved. Claims about human readability of J-space cannot be made from this protocol.

Timing requires special care: generated code is not executed until the response is submitted. A state just before external execution can already contain the entire visible solution. It must not be marketed as an early detector of hidden intent. The final preregistration should distinguish (1) the actual external execution boundary, (2) the beginning of the final code submission, and (3) any syntax-based proxy for commitment to a prohibited operation. Compare a visible-text baseline using exactly the same available prefix. Prefix selection may use external action annotations but must never use either detector's score. A syntax proxy is not the physical action time.

Generic J-lens fitting data must be disjoint from CodeContests and all evaluation tasks; no behavior labels may enter mapping estimation. Preserve the reference estimator's source-position mean, future-target sum, per-prompt averaging and final norm/unembedding conventions. Fit-quality convergence and finite-difference checks remain separate from behavior-detection performance. The reference logit lens is only a baseline.

All current episodes are development data. No test results exist. Repeated seeds and all variants of the same task must remain grouped when future train/validation/test splits are constructed. Easier tasks were added to measure benign yield under the same prompt conditions; difficulty and topic must be checked as confounds rather than using easy-negative/hard-positive separation as detector evidence.

## Required final four-way detection breakdown

The user explicitly requests counts for (1) probe flagged / J-lens did not, (2) J-lens flagged / probe did not, (3) both flagged, and (4) neither flagged. Deliver a table with counts and percentages on the identical paired held-out cases, with thresholds frozen using validation data and the same prespecified observation boundary. Include the total denominator and a case-level CSV with episode ID, task group, independently established behavior label, observation boundary, both scores, both thresholds, both binary decisions, and category. Also stratify this table by independently confirmed misaligned versus benign cases, so agreement is not confused with correctness. Missing scores, abstentions, and unavailable or uncertain behavioral labels must be reported explicitly, never silently counted as unflagged or benign. Four category counts must sum to the paired valid-score denominator; report exclusions separately. Any additional operating points or time boundaries receive separate tables, not pooled counts. If multiple probes are evaluated, identify the prespecified primary probe and provide separate secondary breakdowns.
