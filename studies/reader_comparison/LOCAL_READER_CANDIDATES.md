# Local reader candidate audit

The initial Qwen3.6-27B BF16, greedy, non-thinking candidate produced 48/48 valid bridge judgments but matched the cached premium consensus on only 34/48 (70.83%). It failed the frozen 80% agreement requirement. It passed all 24/24 authored policy fixtures, including 6/6 positives and 18/18 negatives. Both reports, the combined failed gate and exact execution manifest are retained under `evidence/local-qwen-nonthinking-*`. This distinguishes basic explicit policy competence from agreement on the harder interpretability judgments. No production comparative judgments or legacy summaries are authorized through this failed candidate. The original inference implementation, output directory and evidence remain unchanged.

Before reading case-level errors or any held-out study outcomes, the next candidate is the same pinned checkpoint with its native thinking mode enabled and a 4,096-token output budget. This is an adaptive engineering candidate choice after an aggregate validation failure, not an originally preregistered primary setting. The intent is to test whether additional reasoning resolves the disagreement without changing the evidence or scoring rubric. It uses `local_text_reader_reasoning.py`, `local-judge-qwen-reasoning.json`, batch size 4, the same two fixture sets and the same thresholds. All outputs go to a separate directory. No API calls or additional GPU pods are required.

Both bridge and policy checks must pass before production use. Invalid or truncated responses count as failures. A single 8,192-token candidate is allowed only if truncation occurs; all earlier attempts must remain available, and all 72 checks must be rerun with a fresh manifest before adopting that execution. Any further change requires another explicit candidate record. No prompts, labels or thresholds may be tuned to observed individual fixture errors. Passing validation is a usability check against a consensus proxy and authored fixtures, not proof of faithfulness to activations. Candidate selection and the number of attempts must be disclosed in the final report.

If adopted, the reasoning-enabled Qwen execution supplies both summaries and the second judge. The GPT-OSS judge has its own separate checks. All main and legacy calibration remains pending and must use the exact accepted manifests before test inference.

The reasoning candidate completed all48 bridge responses with valid judgments, but matched only29/48 references (60.42%). It therefore also fails the unchanged80% agreement gate; its separate policy check is allowed to finish for documentation. No truncation-based budget retry is justified by these48 responses. Both failed candidates remain excluded from production judgments. These are failures against the consensus proxy, not proof that every disagreement is a factual error.

After these two aggregate failures, one adaptive cheaper-model audit is registered: `google/gemini-3.8-flash`, temperature0, JSON responses, maximum1,600 output tokens, four concurrent requests, identical48+24 fixtures and unchanged gates. It uses only `budgeted_api_client.py`, provider price ceilings of$1/M input and$4/M output tokens, conservative pre-request reservations and no automatic retry. `audit_budgeted_reader.py` tightens the previously unused shared amendment ledger from the$10 outer ceiling to a$1 audit ceiling and re-pauses it on completion or failure. Uncertain reservations stay held. This is the concrete small-audit exception to the inference pause, motivated by failed and slow local-reader validation; it does not authorize a production API restart. Published/model-catalog prices checked before the audit were$0.75/M input and$3.75/M output, within the guard's ceilings. Hosted weights cannot be pinned; raw response model/provider metadata must be retained. Any adoption requires both validation checks and a separately documented calibration protocol.

Completed candidate checks: GPT-OSS-20B passed with 47/48 valid bridge outputs and 39/48 exact agreements (81.25%), plus 23/24 exact policy judgments (95.83%; all six positives and 17/18 negatives). The exact accepted execution and both reports are archived as `evidence/local-gptoss-*`. This qualifies one judge; it does not complete the required pair.

The bounded Gemini audit failed: 48/48 valid bridge outputs, 32/48 exact agreements (66.67%), and 24/24 exact policy judgments. Its execution, reports and cost are archived as `evidence/gemini-audit-*`. Actual audit cost was $0.244215, with zero uncertain reservations; the $1 ledger is paused again. No production use or further API inference follows from this failed audit. Candidate selection remains adaptive and all failures must be disclosed.
